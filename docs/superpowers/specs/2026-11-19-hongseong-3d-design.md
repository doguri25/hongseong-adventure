# 홍성 3D판 설계: 2D 게임을 대신하는 3D 홍성군 탐방

- 작성일: 2026-11-19
- 상태: 승인됨(2026-11-19, "계속 쭉 진행해줘")
- 바탕: 지금 게임 v1.3.6(`dist/`, Canvas 2D), 3D 시험판(`spike/3d-naepo/`, 아티팩트 https://claude.ai/artifact/CE7QA2eHTJ2cpnwttQhnVB), 폭주구구단 `doguri25/pokju-edu` 정식 1.5(원본은 고치지 않음)

## 1. 왜 만드는가

지금 게임은 위에서 내려다보는 2D 지도에서 홍성군 장소 223곳을 찾아가 이야기와 퀴즈를 푸는 초등 3학년 고장 탐방 게임이다. 만든 사람은 폭주구구단 수준으로 그래픽, 화면 디자인, 조작감을 크게 끌어올리고 싶어 한다. 내포 일대 3D 시험판을 여섯 차례 고치면서 다음이 정해졌다.

- 같은 지도 자료(OSM, 실제 고도) 위의 3D 세계가 2D보다 훨씬 생생하다.
- 캐릭터와 탈것은 실제보다 크고(탐험가 키 24 m, 탈것은 그보다 크게) 빠르다(2D 게임과 같은 걷기 초속 78 m, ×4, ×16). 실제 크기·속도로는 이동이 너무 오래 걸린다.
- 한 화면에 넓은 지역이 보이는 "소축척" 화면이 좋다.
- 카메라는 돌리고, 기울이고, 확대·축소가 자유로워야 한다.
- 걷기와 자동차는 건물을 통과하지 않는다.
- 자동차는 도로로만 다니며, 굽은 길은 알아서 차선을 지켜 달리고, 좌우는 갈림길에서 좌회전·우회전을 고를 때만 쓴다.
- 느린 비행기(×4)가 있고 프로펠러는 없다.
- 가로등은 실제 가로등답게 생기고 그럴듯한 자리에 선다.

이 설계는 시험판을 홍성군 전체 게임으로 키워 지금 2D 게임을 **같은 주소에서 대신**하는 일이다.

## 2. 목표, 하지 않을 것, 실패로 보는 것

### 목표
1. 홍성군 전체(약 34.8 km × 26.7 km, 3읍 8면, 섬 포함)를 하나로 이어진 3D 세계로 만든다.
2. 지금 게임의 모든 기능을 그대로 쓸 수 있다: 장소 241곳(지도 223곳과 이야기만 있는 18곳)의 이야기·퀴즈·보상, 오늘의 탐방 미션과 직행 보너스, 발견 수첩과 메모, 꾸미기 상점 22종과 캐릭터 3명, NPC 58명과 대화, 죽도 배 타기, 장소 검색, 전체 지도, 미니맵, 소리와 읽어 주기, 이어하기 파일과 결과 내보내기, 도움말과 자료 출처, QR.
3. 화면 디자인과 구성은 폭주구구단을 따른다(5장).
4. 그래픽은 폭주구구단처럼 화려하고 세밀하다(6장).
5. 아이들의 기록이 끊기지 않는다. 같은 주소에서 같은 저장 형식을 읽고 쓴다.
6. 학교 태블릿에서 돌아간다. 3D가 버거운 기기는 지금의 2D판으로 열린다.

### 하지 않을 것
- 다른 차, 사람의 실제 교통 흐름, 신호등 같은 시뮬레이션.
- 건물 안 들어가기, 실내.
- 실제 가로등·나무 위치 재현(장식으로 표시).
- 서버, 계정, 순위표, 여럿이 함께 하기.
- 장소 이야기·퀴즈 내용 고치기(이번 일은 그릇을 바꾸는 일이다).

### 실패로 보는 것 (돌아가더라도)
- 아이들의 금화·발견·퀴즈·미션 기록이 사라지거나 다시 계산이 달라진다.
- 학교 태블릿에서 너무 느려 수업에 못 쓴다.
- 장식(가짜 건물, 나무, 가로등)을 실제 자료처럼 보이게 한다.
- 글씨가 작거나 버튼이 작아 3학년이 쓰기 어렵다.
- 배포가 깨져 지금 주소가 한동안 열리지 않는다.

## 3. 지켜야 할 조건

- **정적 호스팅만.** GitHub Pages(`https://doguri25.github.io/hongseong-adventure/`)와 Vercel(`vercel.json`, 출력 `dist`)에 그대로 올린다. 서버 없음.
- **저장 형식.** `localStorage['hongseong-adventure-v1']`, `version: 1`, `sanitizeState`(`dist/core.js`)의 규칙을 지킨다. 장소 id를 바꾸거나 지우지 않는다(바뀌면 기록이 조용히 사라진다). 금화·점수는 저장값이 아니라 발견·퀴즈·미션·구매에서 다시 계산된다. 위치의 기준값은 `state.locations.county`(경위도)다. 2D판과 3D판이 같은 출처(origin)에서 같은 키를 함께 쓴다.
- **새 값.** 3D판에만 있는 것(느린 비행기, 카메라·시간·화질·날씨 설정, 2D/3D 선택)은 별도 키 `hongseong-3d-v1`에 둔다. 공유 상태의 `travelSpeed`에는 2D가 아는 값만 쓴다(느린 비행기를 탄 채 저장하면 공유 상태에는 `plane`으로 적고, 3D 키에 실제 탈것을 적는다). 그래서 2D판은 3D가 남긴 기록을 그대로 읽는다.
- **출처 표시.** OSM(ODbL), 고도 자료(Terrarium·USGS·NOAA), 사진 저작권 표시를 지금처럼 유지한다. 장식은 장식이라고 밝힌다.
- **배포를 막는 검사.** 두 배포 모두 `node --test tests/*.test.js`가 통과해야 올라간다. 새 구조에서도 이 검사가 의미 있게 돌아야 한다.
- **인터넷이 막힌 학교망.** Three.js와 글꼴은 묶어서 함께 배포한다(CDN에 기대지 않음).
- **대상.** 초등 3학년. 본문 글씨 15 px 이상, 누르는 곳 44 px 이상, 읽어 주기 유지, 움직임 줄이기 설정 유지.

## 4. 만드는 방법(검토한 길)

| 길 | 내용 | 판단 |
| --- | --- | --- |
| **A. 새 3D 앱이 2D를 대신 (선택)** | Vite + Three.js로 새 앱을 만들고, 지금 게임의 순수 로직 모듈(`core.js`, `quests.js`, `content.js`와 자료 파일, `geography.js`, `wardrobe.js`, `audio.js`, `search.js`의 검색 로직 등)은 그대로 가져온다. 그리는 부분(`world.js`, `cartography.js`, `tile-worker.js`)과 화면(HTML·CSS)은 새로 만든다. 지금 2D판은 `/2d/`로 옮겨 3D가 안 되는 기기용으로 남긴다. | 만든 사람이 고른 길. 폭주식 화면과 3D 세계를 함께 얻고, 기록은 이어진다. 대신 2D판도 계속 관리해야 한다. |
| B. 2D 앱 안에 3D 보기 추가 | 지금 화면은 두고 지도 그리기만 3D로 바꾼다. | 폭주식 화면으로 바꾸자는 요청과 맞지 않아 뺐다. |
| C. 폭주구구단 엔진에 홍성 내용 넣기 | 폭주 코드를 갈라 내용만 바꾼다. | 폭주 엔진은 앞으로만 달리는 4차로 도로 게임이고 2만 행이 한 함수에 묶여 있어 열린 지도에 맞지 않는다. 폭주에서는 그래픽 기술(셰이더, 후처리, 화질 단계, 차량 모델, 화면 디자인)만 가져온다. |

## 5. 화면 디자인과 구성 (폭주구구단 따르기)

폭주구구단 `src/page.html`의 구성과 모양을 따른다: 어두운 유리 패널, 하늘색 → 보라 → 분홍 그라데이션, 둥근 칩과 버튼, 큰 중앙 알림, 원형 계기.

### 5.1 타이틀과 메뉴 (폭주의 `#menu`, 탭)
- 위: 게임 이름, 금화(폭주의 `#wallet`), 이어하기 / 처음 시작.
- 탭(폭주의 `tab-car`·`tab-gear`·`tab-mode`·`tab-rec`·`tab-set`에 대응):
  - **탐방**: 오늘의 미션 세 곳 카드, "탐방 시작".
  - **탈것**: 걷기·자전거·자동차·슈퍼카·느린 비행기·비행기 카드(폭주 `#car-grid`처럼 3D 미리보기 카드). 배율 표시(×1·×2·×4·×8·×4·×16).
  - **꾸미기**: 캐릭터 3명과 상점 6갈래(옷, 수첩, 도장, 발자국, 위치 고리). 지금 가격·규칙 그대로.
  - **수첩**: 발견 수첩(필터, 도장, 메모), 결과 내보내기, 이어하기 파일 저장(폭주 `#pane-rec`처럼 표와 카드).
  - **설정**: 소리·음악·음량·목소리, 움직임 줄이기, 화질(자동·높음·보통·낮음), 카메라 기본값, 시간(낮·노을·밤), 이어하기 파일 불러오기, 처음부터, 도움말·자료 출처·만든 사람, QR, "가벼운 2D로 열기".

### 5.2 탐방 중 화면 (폭주의 `#hud`)
- **왼쪽 위 칩**: 현재 위치(`홍성군 홍북읍`), 금화, 발견 수 / 223.
- **가운데 위 미션 카드**(폭주의 문제 카드 `#obj-*`): "오늘의 탐방 미션", 목표 장소 이름, 진행 점 3개(폭주 `#obj-dots`), 직행 보너스 표시, "길 안내" 버튼.
- **오른쪽 위 미니맵**(폭주의 백미러 자리): 원형 또는 둥근 사각, 북쪽 표시, 누르면 전체 지도.
- **오른쪽 아래**: 원형 계기(속도, 폭주 `#spd-gauge`)와 둥근 큰 버튼들(폭주의 기술 버튼 모양). "탐방(E)", "대화", "탈것 바꾸기". 자동차일 때는 좌회전·우회전 예약 버튼.
- **왼쪽 아래**: 누른 자리에 생기는 조이스틱(시험판과 같음).
- **카메라 버튼**: 확대·축소·기울이기, 나침반(북쪽으로 되돌리기), 카메라 바꾸기(비스듬히 / 뒤따라).
- **가운데 큰 알림**(폭주 `#qtoast`): "도착!", "새로운 발견! +50 금화", "직행 미션 성공!", "정답!" 등.
- **메뉴 버튼**(집 모양, 폭주 `#btn-exit`)과 일시정지.

### 5.3 창들
- **장소 창**: 이야기 쪽 넘기기 → 퀴즈(폭주 `#qbox`의 큰 보기 버튼) → 보상. 정답·오답에 화면 초록·빨강 번쩍임(폭주 grade 셰이더의 flash). 사진과 "실제 사진 / 실제 지형 자료 / 이해를 돕는 삽화" 구분, 자료 출처, 읽어 주기 유지.
- **전체 지도**, **장소 검색(초성 검색 포함)**, **주변 찾기**, **NPC 대화**, **배 타기**, **도움말**: 기능은 그대로, 모양만 폭주식으로.

### 5.4 휴대폰과 태블릿
- 가로·세로 모두 지원. 세로 화면에서는 칩과 미션 카드를 접고 펼칠 수 있다(지금 게임의 접기 설정 키 `hongseong-hud-v1`와 같은 뜻).
- 지금 게임의 터치 처리(글자 선택·길게 누르기 막기 `touch-ui.js`, 안전 영역 여백, 두 손가락 구분)를 그대로 지킨다.

## 6. 그래픽 (폭주구구단처럼)

시험판에 이미 있는 것: Three.js, 폭주 하늘 셰이더(`sky.frag`)와 색 보정(`grade.frag`), 빛 번짐, ACES 톤 매핑, 낮·노을·밤, 화질 자동 단계, 문맥 손실 안내, 실제 고도 지형, 지면 그림과 탐험가 주변 고해상도 다시 그리기, 건물(밤 창문), 나무, 가로등, 물, 폭주 차량 모델, 비행기 두 대.

더할 것:
- **도로**: 차선과 중앙선, 교차로 횡단보도, 보도와 연석, 다리.
- **건물**: 층 띠, 발코니, 옥상 실외기·물탱크, 1층 상가 유리, 학교·관공서 모양 구분, 밤 창문 불빛. 글자(간판, 동 번호, 이름)는 OSM에 이름이 있는 실제 건물에만 붙인다. 장식 건물에는 글자를 넣지 않아 실제 자료처럼 보이지 않게 하고, 도움말과 자료 출처에 장식임을 밝힌다.
- **나무**: 종류와 계절색, 바람에 흔들림.
- **물**: 바다(천수만)와 저수지에 움직이는 물결, 하늘 반사, 해안 물보라, 섬.
- **효과**: 도착할 때 반짝임, 자동차 먼지, 비행기 구름 꼬리, 장소 빛기둥.
- **날씨**(설정): 맑음·비·눈. 비 오면 젖은 도로 반사와 렌즈 빗방울(폭주 1.0~1.1의 표현).
- **탈것**: 자동차·슈퍼카는 폭주 차량 모델(52종 중 고름), 자전거는 새 모델, 비행기 두 대 다듬기, 배(죽도) 모델.
- **캐릭터**: 지금 걷기 그림(8방향 × 4프레임)을 카메라를 향한 판으로 쓴다. 옷 색은 지금의 CSS 필터와 같은 색 변환을 셰이더로 한다. 발자국과 위치 고리도 3D 바닥 무늬로 보인다.

## 7. 세계와 움직임 (시험판에서 정해진 것)

- **좌표**: 지금 게임과 같은 평면 좌표(원점 `[126.4, 36.69]`, x 동쪽, y 남쪽, 미터). 장소·NPC·저장 위치 변환은 지금 공식을 그대로 쓴다.
- **크기·속도**: 탐험가 키 24 m, 탈것은 탐험가보다 크게. 속도는 `78 × state.speed × 배율` m/s(지금 게임과 같음). 카메라는 시험판처럼 멀리(소축척 화면).
- **카메라**: 비스듬히(북쪽 위)와 뒤따라 두 가지. 끌어서 돌리고 기울이기, 두 손가락·휠·버튼으로 확대·축소. 건물이 탐험가를 가리면 그 부분을 비춰 보이게 한다.
- **충돌**: 걷기와 자동차는 건물을 통과하지 못하고 벽을 따라 미끄러진다. 물은 건너지 못한다(지금 `WaterGuard` 규칙, 다리는 통과). 비행기는 건물과 물 위로 난다.
- **자동차·슈퍼카**: 시험판의 도로 그래프 주행(오른쪽 차선 유지, 위 가속·아래 브레이크, 멈춘 채 아래로 차 돌리기, 좌우는 갈림길 회전 예약, 탭하면 길 찾기). 인도·산책로는 못 들어간다.
- **자전거**: 걷기처럼 자유롭게 움직이되 도로 위에서 더 빠르다(정할 것: 15장).
- **비행기**: "뒤따라" 카메라에서는 좌우 방향, 위 가속, 아래 감속. 내릴 때 물 위면 안 됨, 자동차로 내리면 가까운 도로에.
- **걷기 방식과 빠르기**: 지금 저장의 `movementMode`(길로만 / 자유롭게)와 `state.speed`(0.75·1·1.4) 설정을 그대로 쓴다. "길로만"이면 걷기와 자전거가 보행 도로망을 따라 움직인다(지금 `RoadNavigator.move`와 같은 방식). "자유롭게"면 시험판처럼 자유롭게 걷되 건물과 물에 막힌다.
- **장소 도착**: 지금 판정(장소 반지름 36·48 m + 24 m)을 기본으로 하되, 장소 좌표가 건물 안이면 그 건물 벽에 닿을 때, 자동차는 도로에서 110 m 안일 때 도착으로 친다.
- **NPC**: 지금 58명 배치와 대화 그대로. 캐릭터가 커진 만큼 대화 거리를 넓힌다.
- **배 타기**: 남당항 ↔ 죽도 8초 항해를 3D 배와 바다 위 카메라로 보여 준다.

## 8. 자료

- **도로·물길·토지이용**: `dist/map-county.json`(OSM 18,668개).
- **건물**: 게임 지도 933채 + `spike/3d-naepo/data/county-buildings.geojson`(홍성군 전체 OSM 2,075채, overpass-turbo 내보내기) + 내포 `naepo-buildings.geojson`을 OSM id로 중복 없이 합친다. 층수 자료가 거의 없으므로 높이는 종류·넓이로 정한다. 실제 건물이 거의 없는 주거·상업 토지와 마을에는 장식 건물을 둔다.
- **고도**: Terrarium 타일에서 홍성군 전체 높이 격자를 만든다(시험판 `tools/prepare.py`와 같은 방법).
- **장소**: `content.js` 그대로(241곳).
- 자료는 빌드 단계에서 줄이고 나눈다. 좌표 정수화, 구역(타일)별 파일. 처음 열 때 다 받지 않고 가까운 구역부터 받는다.

## 9. 성능

- **화질 단계**: 높음·보통·낮음·자동. 자동은 폭주처럼 해상도부터 낮추고, 그다음 효과를 줄인다.
- **지형**: 구역별 메시와 거리별 세밀도.
- **나무·건물·가로등**: 카메라 가까운 구역만 만든다(인스턴싱).
- **지면 고해상도 다시 그리기**: Worker(OffscreenCanvas)로 옮겨 주 스레드가 멈추지 않게 한다.
- **목표**: 보급형 갤럭시 탭에서 "낮음"으로 초당 30프레임, PC에서 "높음"으로 60프레임. 실제 기기 확인은 만든 사람이 한다(작업 환경에는 그래픽 장치가 없다).
- **2D로 넘기기**: WebGL2가 없으면 시작 페이지가 자동으로 2D를 연다. "낮음"에서도 초당 20프레임이 안 나오면 "가벼운 2D로 열기"를 권하고, 고르면 그 기기는 다음부터 2D로 열린다(설정에서 되돌림).

## 10. 배포 구조

- 새 3D 앱 소스는 저장소의 새 폴더에 두고, Vite로 `dist/`에 빌드한다.
- 지금 2D판은 v1.3.6 그대로 얼려서 `dist/2d/`에 둔다(화면과 로직 사본). 같은 출처이므로 저장이 이어진다. 장소·퀴즈 내용은 한 곳(공유 원본)에서 고치고 빌드가 두 판에 모두 복사한다.
- 루트 주소에는 작은 시작 페이지를 둔다. Three.js와 지도 자료를 받기 전에 WebGL2를 확인해, 없으면 바로 `/2d/`로 보낸다. `?view=2d`·`?view=3d` 주소로 선생님이 한쪽을 고를 수 있고, 아이가 고른 판은 기기에 기억한다.
- Vercel과 GitHub Pages 작업 흐름은 `npm ci && npm run build && 검사`로 바꾼다.
- 바꾸는 날까지 지금 주소는 2D판을 그대로 보여 준다. 3D판은 미리보기 주소에서 확인한 뒤 바꾼다.

## 11. 검사

- 지금 순수 로직 검사(보상, 저장 정리, 미션, 검색, 장소·NPC 수, 물 판정 등)는 그대로 통과해야 한다.
- 2D 화면 문자열을 검사하는 테스트(`arrival-ui`, `mobile-ui`, `phone-controls` 등)와 `World.prototype`을 부르는 테스트는 `/2d/`로 옮긴 2D판에 대해 계속 돈다.
- 3D판의 새 검사:
  - Node: 도로 그래프 주행(차선 유지, 갈림길 선택, U턴, 길 찾기), 건물 충돌, 도착 판정, 저장 왕복(2D↔3D).
  - Playwright 연기 검사: 열기, 콘솔 오류 없음, 휴대폰 세로·가로 배치, 터치 조이스틱.

## 12. 단계

1. **홍성군 전체 3D 세계와 놀이 규칙**: 자료 준비, 구역 불러오기, 지형·바다·건물·나무·가로등, 이동 6종, 장소 도착, NPC, 배 타기, 저장. 화면은 임시.
2. **폭주식 화면과 모든 기능**: 5장 전체. 이 단계 끝에 지금 주소를 3D판으로 바꾸고 2D판을 `/2d/`로 옮긴다.
3. **그래픽 다듬기**: 6장의 "더할 것"과 날씨.

각 단계마다 만든 사람이 확인한다. Vercel 미리보기 주소가 있으면 그것으로, 없으면 단계별 아티팩트(일부 지역)로 보여 준다. 미리보기는 실제 서비스 출처를 쓰지 않으므로, 2D↔3D 저장 왕복은 자동 검사와 이어하기 파일로 확인한다.

## 13. 만든 사람이 정한 것

- 2D를 대신하는 3D판(같은 주소, 기록 그대로, 버거운 기기는 2D).
- 화면 디자인·구성은 폭주구구단처럼.
- 홍성군 전체.
- 그래픽은 폭주구구단처럼 화려하고 세밀하게.
- 7장의 크기·속도·카메라·충돌·자동차·비행기·가로등 규칙(시험판에서 하나씩 정함).

## 13-1. 답을 받지 못해 가정한 것 — 바꿀 수 있음

- **기기**: 보급형 갤럭시 탭(2~3GB RAM급)에서 크롬·삼성 인터넷, 그리고 교실 PC(크롬·엣지·웨일). 아이패드·크롬북은 "되면 좋음". 처음 열 때 내려받는 양은 10MB 안팎을 목표로 하고, 지도 자료는 가까운 구역부터 받는다.
- **주소**: GitHub Pages와 Vercel 두 곳을 같은 날 함께 바꾼다(둘 다 같은 `dist/`에서 배포). QR이 가리키는 chatgpt.site 주소는 이 저장소가 배포하지 않으므로 바꾸지 않고, QR은 GitHub Pages 주소로 고친다.
- **마감**: 따로 없음. 단계마다 확인받고 2단계 끝에 바꾼다.
- **건물 자료**: OSM(게임 지도 + 홍성군 전체 내보내기)과 장식 건물. 나중에 GIS건물통합정보를 받으면 자료 단계만 바꿔 넣는다.

## 14. 내가(Claude) 정한 것 — 바꿀 수 있음

- Vite + Three.js(버전 고정) 빌드, 3D 소스 새 폴더, 2D판은 `/2d/`.
- 3D 전용 설정은 별도 키 `hongseong-3d-v1`.
- 일방통행은 막지 않고 길 찾기 비용만 높인다(다른 차가 없으므로).
- 단계 순서(세계 → 화면 → 그래픽).
- 2D판은 v1.3.6으로 얼리고, 내용(장소·퀴즈)만 공유 원본에서 두 판에 복사.
- 루트 시작 페이지: WebGL2 없으면 자동 2D, 느리면 권유 후 기기에 기억, `?view=2d|3d`.
- 느린 비행기 등 3D 전용 값은 3D 키에, 공유 상태에는 2D가 아는 값만.
- 걷기 방식(길로만/자유롭게)과 빠르기 설정은 지금 저장값 그대로 유지.
- 장식 건물에는 글자 없음.
